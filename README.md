# 校园活动管理系统 V2.0

软件工程实验成果。实验一《基于工程意图的软件迭代开发》完成 V1.0，
实验二《基于用户访谈的需求演化》在 V1.0 基础上迭代为 V2.0。1 人小组完成。

## 技术栈

- 后端：FastAPI（Python）+ SQLite（标准库 sqlite3）
- 前端：Vue 3（本地 vendor 引入，无构建步骤、离线可用）+ 原生 HTML/CSS/JS
- 部署：同源部署（FastAPI 托管前端静态文件），本地运行

## V2.0 新增功能（对应需求 R-01~R-08）

| 角色 | 新增功能 |
|---|---|
| 学生 | 满员后报名转入**候补队列**（不再被拒）；报名状态区分**待审核 / 正式参加 / 候补中**；候补可主动退出 |
| 教师 | 按活动设置**是否需要审核**与**参加资格**；审核本人活动收到的报名（通过后按剩余名额定正式或候补）；报名名单按状态分组，候补按进入候补时间排序 |
| 系统管理员 | 查看平台全部账号及角色、**停用异常账号并在处理后续恢复**（停用后无法登录，已登录会话立即失效） |
| 系统规则 | 正式名额空出后由候补顺序最靠前者**自动递补**；正式人数只统计正式参加，候补与待审核不占名额 |

## 功能（V1.0 基线，对应需求 REQ-01~08）

| 角色 | 功能 |
|---|---|
| 所有用户 | 注册（学号/工号+姓名+密码+角色，仅学生/教师）、登录、退出登录（服务端注销 token） |
| 学生 | 浏览活动广场（含发布教师）、报名/取消报名、我的活动 |
| 教师 | 发布活动、管理自己发布的活动（编辑/取消）、查看本人活动的报名名单 |
| 系统规则 | 名额上限、活动开始后不可报名、同人不可重复报名、密码哈希存储、教师不可报名 |

## 本地启动

前置：Python 3.10+，安装依赖：

```bash
pip install -r requirements.txt
```

项目根目录执行（首次会自动建库并写入演示数据）：

```bash
uvicorn backend.main:app --reload --port 8000
```

浏览器打开 http://127.0.0.1:8000 即可使用。
接口文档（FastAPI 自带）：http://127.0.0.1:8000/docs

## 项目结构

```
backend/            FastAPI 后端
  main.py           应用入口（路由注册 + 静态托管）
  database.py       数据库层（建表 + 演示数据 + 演示活动顺延）
  auth.py           认证（密码哈希 + token + 账号状态校验）
  helpers.py        活动/报名状态与字典转换公共函数
  routers/          业务路由（users/activities/registrations/admin）
frontend/           Vue3 前端（index.html + app.js + style.css + vendor/ 本地依赖）
tests/              软件验证自动化脚本（test_api.py，REQ-01~08 与 R-01~R-08 共 36 条用例）
docs/               需求、工程意图、决策、设计文档
project-data/       实验过程数据记录
report/             实验报告工作副本（仅本地，不提交）
```

## 已知说明

- 认证 token 存于服务端内存，重启后需重新登录（实验规模简化，见 docs/04-软件设计.md 决策 4）；
- 演示数据库文件 `backend/activity.db` 自动生成，已加入 .gitignore 不提交；
- **演示活动的时间会自动顺延**：演示活动按"当前时间 + 30/45/60 天"生成，若数据库放置较久、活动已开始（状态变为「已截止」），
  下次启动服务时 `init_db()` 会自动把它们的起止时间顺延到未来，保证任何时候打开系统都能演示报名与候补；
  只处理标题在白名单内的演示活动，自己新建的活动不受影响；
- **演示数据已预置三种报名状态**：首次建库时会写入三条演示报名
  （人工智能前沿讲座 = 待审核、摄影技巧分享会 = 正式参加 / 候补中），
  打开系统即可直接演示审核与候补功能，无需先手工造数据；
- V2.0 变更了 `users`/`activities`/`registrations` 三张表的结构。
  因 SQLite 无法直接修改已有的 CHECK 约束，本项目采用**删库重建**的方式升级：
  删除 `backend/activity.db` 后重启即可（演示数据会重新生成）。
