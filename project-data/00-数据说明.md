# 00 项目数据说明 —— 数据记录体系与报告映射

> 本目录是项目的**过程数据仓库**：记录开发过程中产生的操作步骤、参数、观测结果、异常与处理。
> 原则：数据先记录，报告后生成。项目完成时，基于 `docs/`（正式交付物）+ `project-data/`（过程证据）自动合成完整实验报告。

## 1. 数据文件结构

| 文件 | 记录内容 | 状态 |
|---|---|---|
| 01-实验信息.md | 实验基本信息、小组分工、工具、时间线 | 已补录 |
| 02-AI辅助过程记录.md | 每次 AI 交互：阶段/上下文/AI建议/小组判断/成果 | 已补录（持续追加） |
| 03-Git与实现记录.md | Git 提交表、代码结构演进 | 已补录（持续追加） |
| 04-异常与处理记录.md | 错误现象、原因、处理过程、结果 | 已补录（持续追加） |
| 05-验证与观测记录.md | 测试用例、预期/实际结果、观测数据 | 待填（阶段⑤启动） |

## 2. 与实验报告模板的映射关系

| 数据来源 | 报告章节 |

| 05-验证与观测记录.md | 七、软件验证（7.1 验证方案与结果 / 7.2） |

## 3. 记录维护规则

1. 每完成一个工作轮次（需求/设计/编码/测试/部署），由 AI 自动追加对应记录；
2. Git 提交后同步更新 03 文件（commit id、时间、说明、对应需求）；
3. 任何报错、异常、纠正过程立即记入 04 文件（现象/原因/处理/结果）；
4. 数据只追加不覆盖，保留完整过程轨迹；
5. 涉及敏感信息（密码、Token、密钥）一律不记录、不提交。

## 4. 报告自动生成计划（项目完成时执行）

1. 汇总读取 `docs/` + `project-data/` 全部数据；
2. 生成必要图表：Git 提交时间线、测试通过率、模块完成度等；
3. 按报告模板结构填入：实验目的 → 方法步骤 → 原始数据 → 结果分析 → 结论；
4. 输出完整 docx（按 tencent-docs 流程处理模板文件），确保与代码、仓库一致。
